# Implementation decisions

`SPEC.md` remains the source of truth. M1–M6 are implemented; current verification results and remaining environment limits are tracked in `PROGRESS.md`. The entries below preserve the decisions made during each milestone. Milestone commits remain unavailable because this workspace has no Git metadata.

1. **Additional YAML dependency:** the spec requires YAML front matter but names no YAML deserializer. Use `serde-saphyr = 1.3.0` with only `deserialize` enabled. It supports WASM and does not enable filesystem includes. JSON values provide recursive, explicit-field merging; absent fields preserve the selected theme.
2. **Syntax engine on WASM:** disable comrak's default CLI/highlighter features and use syntect's explicit `parsing`, `default-syntaxes`, `html` and `regex-fancy` features, avoiding native Oniguruma and production plist/YAML loading. The development syntax generator enables plist loading separately. WASM compilation passes. Syntect still includes dormant filesystem APIs and walkdir transitively; core uses only in-memory parsing/default syntax data.
3. **Partial theme files:** deserialize omitted sections/fields from defaults. Built-in TOML files contain preset differences. A document `theme: academic` explicitly selects that preset; nested document fields override it. A document theme mapping merges into user edits, with root-level overrides winning. Invalid overrides produce diagnostics and retain the user theme.
4. **CSS safety:** accept at most 50 KB of custom CSS. Reject the entire custom stylesheet on at-rules, backslashes, HTML delimiters, comments, URL functions, expressions, or unsupported control characters. This is intentionally more restrictive than removing external URLs: escaped/comment-obfuscated CSS cannot bypass the filter. Generated colours use a hex/keyword allowlist. Header/footer content uses CSS string escaping and explicit counter tokens.
5. **Asset resolution belongs outside core:** Markdown asset IDs become `/assets/<id>`. Core never fetches remote images or opens files. Unresolved paths/remote images produce diagnostics. Native asset resolution and upload handling remain for later milestones; they must feed the same core builder for preview and PDF.
6. **CSP nonce ownership:** the pure builder emits a nonce placeholder. `PrintDocument::with_nonce` binds a fresh nonce provided by the delivery layer without rewriting ordinary Markdown text. Both delivery paths must bind it before loading the document. Randomness must stay outside core. Delivery must also call `with_embedded_assets` with trusted base64 vendor assets. This rewrites only generated CSS and the controlled Mermaid script reference; data font URLs avoid opaque iframe asset-origin/CORS dependencies. Real Chromium checks pass with `sandbox="allow-scripts"`. The native fixture example performs file reads outside core; native production delivery is implemented in M2; web delivery remains M3.
7. **Syntax palettes:** complete upstream theme resources and MIT license notices are vendored at immutable revisions in `assets/syntax/manifest.json`. Nord is converted from Sublime format to TextMate. Syntect generates the full CSS, scoped to code blocks. Syntax token rules do not override the user-selected code background.
8. **Version pins:** Leptos `=0.8.22` is reserved in the workspace, based on [published documentation](https://docs.rs/leptos/0.8.22/leptos/). Mermaid `11.17.2` is the selected 11.x asset version, based on the [npm version history](https://www.npmjs.com/package/mermaid?activeTab=versions). CodeMirror's selected umbrella package is `6.0.2`; its complete editor dependency bundle will be pinned before M3. No vendor artifact is claimed present until downloaded, licensed, and checked in.
9. **Milestone gate:** network restrictions are not grounds to substitute a different Markdown parser, skip ammonia, fabricate snapshots, or declare checks passed. M2 required real workspace checks, reviewed snapshots, vendoring and the core WASM build to pass. This gate passed before M2 began.

## M2 implementation decisions (2026-10-23)

1. **Native dependencies:** pin chromiumoxide 0.9.1, lopdf 0.46.0, Tokio 1.54.1 and clap 4.6.7. Supporting direct dependencies are futures-util 0.3.34 (poll the CDP handler/event streams), base64 0.23.1 (typed embedded assets), getrandom 0.4.3 (unpredictable CSP nonces), and tempfile 3.27.0 (private browser profiles and test outputs). The spec omits these support crates; they are required by the chosen native APIs or their lifecycle/security needs. No named renderer/parser is substituted. These dependencies stay out of core.
2. **Portable assets:** a native build script embeds the vendored Mermaid file and all declared WOFF2 subsets. Native delivery base64-encodes them once and reuses the map. Core asset binding now assembles CSS in a single pass rather than repeatedly copying the growing embedded stylesheet. Binaries require no runtime source checkout or CDN.
3. **Pool and restart ownership:** one browser process serves reusable worker tabs with a bounded queue. Each export has one deadline covering preparation/queue/render work. Workers skip already-cancelled queued jobs. A failed browser operation retries once, with generation checks preventing simultaneous workers from repeatedly replacing the same crashed process. A timed-out tab is closed and replaced. Browser profiles are private temporary directories; explicit shutdown closes/reaps the process.
4. **Network isolation:** since fonts and Mermaid are embedded, Chromium blocks every external request, including arbitrary HTTP/file asset routes. Data/about:blank resources need no remote origin. Future asset-store delivery must resolve/inline approved image bytes before rendering; the current CLI does not fetch local/remote Markdown image paths. Tests bypass core CSP deliberately and verify an HTTP probe never reaches a local listener.
5. **Vector effects and measured bounds:** Chromium rasterizes Mermaid timeline groups using the CSS brightness filter. Shared core CSS disables SVG filters for diagrams so both preview and PDF retain vector output. Mermaid also underestimates view boxes for Gantt, XY and tree-view diagrams. The common bootstrap expands view boxes to include measured bounds and four units of padding. Real-browser assertions verify all 34 fixture diagrams fit their view boxes and have no rasterizing filters; the exported Mermaid PDF has no image XObjects.
6. **PDF verification tools:** lopdf writes UTF-16BE Title/Author/Subject/Keywords and checks PDF structure, page boxes and outlines. Its text extractor did not decode Chromium 155 subset-font CMaps correctly in this environment; Poppler `pdftotext` verifies text and pagination instead. Chromium's embedded CJK Type 3 glyph programs are accepted alongside FontFile2/FontFile3 programs; `pdffonts` confirms embedded subsets and Unicode maps. Selected CJK and Mermaid pages were also rasterized and visually inspected. Full visual goldens remain M5 work.
7. **CLI behavior:** the CLI uses one worker tab, supports presets/TOML and repeated typed dotted overrides, and writes optional HTML identical to renderer input. Front matter keeps its higher precedence. Strict diagram errors return code 2 before output writes. Destinations are resolved through their parent directory to detect aliased PDF/HTML paths and avoid overwriting the Markdown input.
8. **Milestone boundary:** the previous M1 verification gate passed before M2 began. Missing Git metadata prevents commits but does not prevent implementation and verification of the next milestone after the user's explicit continuation. M3 web export/preview will consume the same native preparation and pool API; HTTP 422 mapping remains part of M3.

## Completed app and delivery decisions (2026-10-23)

1. **Real Leptos state and transport:** SSR and hydrate share one Rust component tree. A `wasm-bindgen` bridge owns Leptos Markdown/Theme signals and the CSS memo; CodeMirror communicates through that bridge. Preview uses the actual JSON-coded Leptos server function at `/api/rpc/render_preview`; `/api/preview` is an equivalent convenience route. Binary PDF export remains an Axum route.
2. **Build consistency:** cargo-leptos 0.3.6 is pinned because 0.3.11's locked dependencies require a newer Rust than this workspace. Component erasure is disabled explicitly so plain Cargo and cargo-leptos builds hydrate consistently. `.cargo/config.toml` sets the output name/site path, avoiding the runtime `_bg.wasm`/`.wasm` naming mismatch. The build tool's wasm-bindgen CLI version follows the exactly pinned Rust dependency.
3. **Frontend delivery:** CodeMirror 6.0.2 and its Markdown/CSS/search/lint dependencies are exact npm dependencies with a lockfile. esbuild creates a checked-in ESM vendor bundle and license inventory. Runtime assets use local paths. Plain JavaScript handles browser APIs and CodeMirror; typed theme compilation and structural rendering remain in Rust/WASM.
4. **Theme changes:** visual changes replace CSS and Mermaid config locally. TOC, numbering, code line numbers and other structural settings call the same `build_print_document` in WASM and replace the sanitized main fragment. The iframe preserves resolved image figures and embedded fonts. This avoids duplicating Markdown transformations in JavaScript or requiring theme-only server round trips. Uploaded font data is registered locally and supplied to the opaque iframe so switching between uploaded families remains local.
5. **Assets:** uploaded content is SHA-256-addressed beneath random session directories; HttpOnly/SameSite cookies scope access. The same native preparation layer resolves web uploads, CLI relative files and public remote Markdown images, inlining all bytes before rendering. Remote requests validate every DNS result/redirect, pin approved addresses, bypass proxies, cap bytes and use timeouts. Limits include 50 document images, a 64 MB asset budget, 100 uploads and 10 custom fonts per session. TTL cleanup runs hourly. Extra dependencies (Axum, tower-http, reqwest, sha2, JS/WASM bindings) supply the specified HTTP, hashing, networking and interop features rather than substituting a different stack.
6. **Font delivery:** native preparation keeps every bundled family available but embeds only Unicode subsets intersecting document text/metadata. Noto fallbacks cover missing CJK glyphs. Frontend font samples use the same bundled files. Uploaded fonts are validated by the browser and embedded into native PDFs. Chromium may use Type 3 Unicode vector glyph programs; tests inspect FontDescriptor names, including uploaded Merriweather, rather than requiring Type 0 font dictionaries.
7. **Diagram caching and determinism:** the iframe reuses trusted SVGs keyed by source, config, element identity and available width. Cache data is injected as nonce-bound JSON and never comes from Markdown HTML. Mermaid 11's `run()` seeds SVG IDs from the *length* of `deterministicIDSeed`, producing collisions across independent renders. The bootstrap instead calls `mermaid.render` with an explicit unique stable ID. A scoped, source-seeded PRNG makes automatic Git graph commit labels/layout randomness repeatable; the original random function is restored after each render. Both outputs run this identical bootstrap.
8. **Running sections:** Chromium supports page margin boxes/counters but not CSS named strings. When `{section}` is used, export reads top-level outline destinations from the actual first PDF pass, prints the same document's page ranges with the correct label, and replaces page drawings/resources while retaining the original catalog, bookmarks and tags. This avoids estimating print pagination from screen coordinates. Jobs still share the original 30-second deadline. A three-page test checks continuation pages, section changes and `Page X of Y`.
9. **v1.1 features:** KaTeX 0.19.0 and WOFF2 fonts are vendored with MIT notice and checksums, loaded only for math documents. TeX trust is disabled and expansion/size bounded. `cover: true` is typed front matter and creates a shared-renderer title page. Images and diagrams have independent figure-number sequences. `.tmTheme` uploads are parsed by native syntect, converted into scoped, sanitized CSS and saved in `Theme.code.custom_syntax_css`, so imported styles also compile offline in WASM and round-trip through TOML.
10. **Delivery checks:** Playwright 1.64.1 selects Chromium 156.0.8078.4 revision 1248 for browser tests, container and PDF visual baselines. Poppler’s Cairo backend rasterizes PDFs and `pdftotext` verifies Unicode text; pngjs compares pixels at a 0.5% tolerance. CI includes ordinary/ignored Rust suites, sandbox browser checks, E2E, CLI/web parity, visual goldens and a container build/health check. Docker became available during the follow-up: a clean image build, health check, all eight browser tests, CLI/web fixture parity and all 16 visual baselines now pass against the container. Its bundled CLI also exports the math/cover fixture successfully. See `docs/container-verification-report.json`. Hosted CI execution remains unverified, and this workspace still has no usable Git metadata.

11. **Raster backend:** inspection found that Poppler Splash (`pdftoppm`) drops some Chromium Type 3 glyphs, such as the initial M in the Mermaid fixture title, while its Cairo backend draws the same PDF correctly. Visual goldens therefore use `pdftocairo`, retaining the specified Poppler-based verification and pixel tolerance. The math/cover fixture also has a page-two golden so formulas are actually inspected.

## Preview performance (2026-10-24)

1. **Keep the document runtime alive:** normal preview updates patch the sanitized `<main>` fragment inside the existing opaque iframe. Unchanged top-level blocks retain their DOM, rendered SVGs, decoded images and math. Embedded font faces accumulate as new glyphs are needed. The original native document endpoint still supplies the initial nonce-bound sandbox; `render_preview_update` supplies compact native updates without retransmitting Mermaid. KaTeX is supplied once when first needed. Standalone HTML/PDF delivery retains the shared print document.
2. **Render Rust off the UI thread:** a module worker loads the same optimized WASM and calls a DOM-independent Rust entry point. It returns body markup, CSS, diagnostics and effective front matter. The native path handles unresolved image assets and new Unicode font coverage; unavailable workers also fall back to this path. Request revisions discard stale results. Text appears before newly needed fonts finish loading; diagram measurement waits for those fonts. Request invalidation cancels the remaining obsolete diagrams after the current Mermaid call finishes. Theme changes during an in-flight request restart it with the latest settings.
3. **Bound scrolling work:** frame geometry is indexed after content/layout changes. Scroll messages are coalesced per animation frame and use binary search over cached source-line/position arrays. The editor uses its actual visible line instead of CodeMirror's overscanned viewport boundary. No full-document geometry scan runs for an ordinary scroll event.
4. **Avoid repeated setup:** Syntect's syntax definitions initialize lazily once per native/WASM instance, and theme compilation no longer parses the entire document just to retain math CSS. Mermaid loads its configured diagram font and Noto fallbacks rather than every bundled family. Interactive rendering yields between expensive diagrams. File opens/drops bypass the typing debounce, and capture-phase drop handling prevents CodeMirror from processing the same file again.
5. **Optimize the normal local command:** both development and production browser builds select `wasm-release`; the development server keeps its normal native profile. Performance verification separates content replacement from complete diagram/font readiness and exercises real file drops with the supplied Markdown samples. Absolute timings are local measurements, not portable latency guarantees.
